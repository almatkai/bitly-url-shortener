Known presentation limitations at the frozen host: `List.EmptyView` ignores its icon property, so both original empty-state PNGs are packaged but are not shown by that host. The extension uses no remote favicon traffic. The host exposes final-result effects rather than a streaming toast service: normal shorten remains automatic, but animated “Shortening”/success effects arrive with completion. These differences are explicit and need desktop review.

No reverse RPC effects are executed by the QA harness: selection/clipboard replies and write/paste/open/settings acknowledgements are injected. The exact contracts are string selection/clipboard reads, `{text}` writes/pasteText, `{target}` shell opens and `{surface:"settings-extensions"}` settings opens. Only `{ok:true}` with optional string `message` acknowledges an external action. Booleans, null, extra keys and contradictory errors fail. `pasteText` owns its own write/hide/focus/paste sequence; the adapter does not separately hide the window or paste twice.

The host must honor one live executable per extension/profile, serialize that profile's storage ownership, fence generations, dispose no-view sessions, kill the process tree after its graceful shutdown boundary and never replay action/POST requests. Cancellation cannot undo a remote shortening or a clipboard/paste action. SDK staging protects only successful current in-memory state; recovery markers deliberately persist outside that staging. A canceled open removes adapter authority through its drop guard even if the host loses the renderer recovery view; the scoped private recovery record survives for a later command opening.
