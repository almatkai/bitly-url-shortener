Manifest OS verification accurately remains `not-run`. The inactive CI example is not evidence that CI has run.

The complete host app and complete archive installer were not built/executed. Only the exact independent extracted fixture surfaces described above were executed. The integration patch is unapplied. Known UI adaptations and frozen renderer limits are listed in INTEGRATION.md. Exhaustive Unicode WHATWG conformance, all platform filesystem races, adversarial same-user replacement of the host-private directory tree, real proxy infrastructure and full Bitly schema variations are outside the synthetic evidence. The host private path is a trust boundary, not an OS sandbox.

Recovery cannot create a distributed transaction: POST/clipboard/paste effects can complete after cancellation or lost ACK. No automatic POST retry exists. Unknown creation markers and exact prepared responses are retained, with a 64-record/128-KiB bound; acknowledged records may be evicted to preserve capacity. If all slots remain unresolved, new shortening is refused rather than dropping uncertainty. Process-independent scope keys prevent ordinary credential/profile cross-use, but loss/removal of private data or changed original input/credentials removes that recovery identity. Errors explicitly tell the user when a deliberate retry may create a duplicate.
